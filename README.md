# Доля — личная CRM проджект-менеджера

Учёт проектов, этапов, бонусов и фактически полученных денег. Интерфейс на русском, суммы в рублях.

## Запуск

Нужен Node.js 24 и npm.

```sh
npm ci
npm run dev
```

В облачной среде используйте существующий checkout `/workspace/codexCRM`. Задача уже изолирована, отдельный Git worktree не нужен.

```sh
npm test           # Проверки финансовой логики
npm run build      # Проверка TypeScript и production-сборка в dist/
npm run preview    # Локальная проверка production-сборки
```

## Первый запуск

Новое пространство открывается без тестовых проектов и поступлений. Добавьте свой проект, его этапы с бюджетами и при желании ссылку на Google-таблицу.

В старом пространстве с отметкой демо известные стартовые проекты удаляются автоматически. Личные проекты сохраняются; зарплатные записи в смешанном пространстве сохраняются, поскольку их нельзя надёжно отличить от примеров. До очистки исходная JSON-копия сохраняется в браузере и доступна в настройках кнопкой **«Копия до обновления»**. Если отметки демо нет, данные не очищаются.

## Правила расчёта

- Фиксированная часть: 20 000 ₽ первого числа и 20 000 ₽ пятнадцатого. Новые условия можно запланировать в настройках с будущего месяца; прошлые условия сохраняются.
- Ставка бонуса по умолчанию — 7%. Каждый этап сохраняет собственную ставку, изменение общей настройки не пересчитывает старые этапы.
- Бонус = бюджет этапа × ставка с округлением до копеек.
- До закрытия этапа бонус входит в прогноз, но недоступен к получению. После закрытия начисляется на ближайшее 1-е или 15-е число, включая сам день закрытия.
- Получение отмечается вручную, в том числе частями. CRM не проводит банковские переводы. Переплата и будущая фактическая дата не допускаются.
- «План дохода» относится к плановой дате выплаты; «Получено» — к фактической дате поступления. Позднее получение будет показано в месяце, когда деньги действительно пришли.
- Просроченные начисления видны за всё время, включая прошлые месяцы; смена месяца не скрывает задолженность.
- Архивирование проекта сохраняет этапы, начисления и поступления.
- Этап с поступлениями нельзя удалить или отредактировать. Ошибочное поступление можно удалить одним нажатием корзины в истории выплат и затем исправить этап. Сумма возвращается в остаток к получению.
- Проект можно удалить одним нажатием корзины в списке или кнопки в карточке. Его этапы и связанные поступления удаляются вместе с ним.
- После удаления доступна кнопка **«Вернуть»**. Последовательные удаления можно отменить в обратном порядке до перезагрузки страницы или закрытия сообщения. Возврат сохраняет другие изменения и не допускает переплаты.

## Напоминания

За два дня до плановой выплаты внутри CRM появляется уведомление с датой и неполученной суммой. Оно включает оклад и бонусы закрытых этапов, обновляет остаток при частичном получении и исчезает после полной выплаты. Если открыть CRM за день до выплаты или в день выплаты, напоминание тоже будет видно. Даты считаются по Asia/Tomsk и обновляются при открытой странице и возвращении к ней. При закрытой CRM системные уведомления не отправляются.

## Хранение и резервные копии

Первая версия работает локально: `localStorage`, ключ `dolya-crm-v1`. Данные доступны в том же браузере и на том же origin (протокол, адрес и порт). Dev-сервер и preview используют разные порты и отдельные хранилища. Очистка браузера удаляет данные; синхронизации между устройствами и серверной базы пока нет. Не используйте общий профиль браузера для личных финансов.

В **Настройках → Резервная копия** можно скачать JSON со всеми проектами, этапами, условиями оклада и поступлениями. Восстановление проверяет структуру, даты, суммы, ссылки и целостность выплат, затем просит подтвердить замену данных. Храните копии в безопасном месте: они содержат ваши финансовые сведения.

Google-таблицы используются как ссылки на бюджеты. Чтение таблиц, импорт произвольных CSV и OAuth пока не реализованы. Секреты и Google API credentials не требуются.

## Проверки интерфейса

Проверены создание проекта и этапа, закрытие, частичная и полная выплата, отмена поступления, перезагрузка, экспорт/импорт, отклонение неверной копии, мобильная навигация и отсутствие горизонтального переполнения на 390, 768 и 1440 px. Исходники финансовых тестов: `src/domain.test.ts`.

Сквозной браузерный тест: `python3 scripts/smoke.py` при запущенном `npm run preview -- --port 4173`. Нужны Python Playwright и Chromium (в текущей облачной среде доступны). Тест использует отдельный временный профиль и вымышленные данные; ваши записи не затрагиваются. Адрес можно изменить через `CRM_TEST_URL`, путь к Chromium — через `CRM_BROWSER_PATH`. Скриншоты сохраняются в игнорируемой папке `test-results/`.

Проверка напоминаний с управляемыми датами и очистки старых примеров: `python3 scripts/reminders-smoke.py` при работающем preview.

Автономный HTML: `npm run build`, затем `python3 scripts/export-html.py` (создаёт `dist/dolya.html`). Можно передать другой путь выходного файла. Перед заменой HTML скачайте JSON-копию в старой версии и восстановите её в новой.
